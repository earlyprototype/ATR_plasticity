## 1. The answers in brief

**The idea is that the write channel this project built might carry a context the model was given, so that the context could then be cleared; whether it carries anything specific to the context is an open question, and the pilots say that on one fact the model binds in context the write moves the answer the wrong way, that on one topic the colouring moves a little, and that a gain on the format context seen in the first token of its answer disappears when the whole answer is scored; a further measurement shows that the score the earlier protocol used for facts could not tell binding from priming, and the protocol now separates them.** The project showed that a Hebbian write, driven by the model's own activity, changes one weight matrix in a way that changes later behaviour. The prior-art file records that a Hebbian outer-product matrix is how a linear-attention model stores its context, with the condition that this applies if the project ever drifts an attention matrix, which it has not. At the feed-forward site every result uses, the write amplifies whatever the context activated; it is not a store of separately supplied keys and values. So the honest statement is that the channel is Hebbian in form, that a Hebbian matrix can in principle store context, and that whether this one does is exactly what has to be measured. Section 2 has the idea in one page.

**The technical elements are a context window, a key-value cache, a weight matrix, an outer product, and one way of measuring what a write carries that the same write from a different context would not.** Each is explained in ordinary words in section 3, with a table of the sizes involved. The measurement that matters compares the model's own-context write against writes made from other contexts, because a reviewer's re-run of the first pilot with a swapped-context arm found that a write from an unrelated context scored as well as the right one.

**Nineteen pieces of published work sit near this, in seven groups, and for the five groups that are method families the project's difference is a different one for each.** For the architectures that update weights while reading, the model here is frozen and was never trained to be written into. For the methods that fold context into weights by training, the rule here is fixed and needs no gradient. For the weight-editing methods, the write here never sees the query. For the vector-transfer methods, the object here is a weight change rather than an activation. Section 4 describes each work in a few sentences with a link.

## 2. The idea, in one page

**What the project has.** The parent project runs GPT-2 Small in a closed loop: it reads the model's residual stream, the running vector each layer reads from and adds to, at the last block, rescales it, and writes it back into the first block, hundreds of times. This repository lets one weight matrix change while that loop runs, under a Hebbian rule: the matrix is nudged in proportion to the product of the activity entering it and the activity leaving it. EXP-001 measured that at the sixth block's feed-forward output matrix this write, at 1.12 percent of the matrix's size, moves the loop's settled state from one basin to another on three of three prompts (register rows C-20 and C-21). A rank-one random write matched on how far it displaces the loop's state also moves the basin, four times in six, but never to the same destination and only at 66 to 172 times the weight cost (register row C-55). That is established.

**What the prior-art file already says about that write.** The entry for Schlag, Irie and Schmidhuber's 2021 paper reads, in its own words: "If we ever drift an attention matrix we are formally running a fast-weight programmer whose keys and values are self-generated." A fast-weight programmer, in that paper, is a model that stores its context by summing, over every context token, the outer product of a key vector and a value vector into a matrix. That is established from the file and from the paper.

**What the write actually is at the site the project uses.** Every committed result and both pilots are at a feed-forward output matrix, where the output is the input times the matrix plus a bias. Register row C-10 records the Hebbian write there exactly: the input's second-moment matrix times the existing weight, plus the mean input times the bias. In plain words, the write amplifies the directions the context activated in the matrix it already has, and adds a bias term. Both operands come from one matrix's input and output; nothing supplies a key and a value separately. That is established from the record.

**The deduction, stated at the strength the record supports.** A Hebbian outer-product matrix can store context: that is the linear-attention result. This project's write is Hebbian in form. So it is worth asking whether a context fed through the channel leaves anything specific to that context behind. Because the write is an amplifier of activated directions rather than a key-to-value store, the expectation is that it carries the context's general colouring rather than any binding between words. Both sentences are inferences, and the second is the pre-registered expectation in `EXP_004_SPEC.md`.

**The consequence, which is where the session's framing began.** A context held in a model's context window costs memory that grows with every token, in a structure called the key-value cache. A weight change costs a fixed amount however long the context was. A channel that moved context out of the window and into the weights would be a memory-management step for any long-running use of a model. That is an inference, and section 3 gives the sizes.

**Where this sits.** The closest published shape is Lee and colleagues' 2026 paper, already in the prior-art file as "the closest loop shape": pause, fold the accumulated context into fast weights, discard the key-value cache. What is proposed here is that procedure with this project's fixed, target-free rule and frozen model in place of a learned rule and a trained model, and with one comparison no published work has run: folding after the project's free-running loop, which reads no stored context at all. That is an inference about the literature, from the entries the prior-art file holds.

**What it changes for this project.** It supplies a target without adding a task: the reference is the model's own behaviour with the context present, and the score is how far the model with the context removed and the write installed sits from that reference, compared with how far it sits after a write made from a different context. That score is continuous and comparable across sites, rules, step sizes, loop lengths and models, where the project's primary readout so far has been a basin label. It also states the difference from weight-editing methods, which `ALIGNMENT_REVIEW.md` section 6 warns a reviewer will raise first, as a measurement: register row C-43 puts the difference in three parts, that the edit here is derived with no target, from the model's own activation statistics, and read out on the iterated map's attractor structure, and the proposed experiment puts a number on the first of those. These are inferences about method.

**Where the room analogy holds and where it stops.** In the project's founding image, Lucier's recording played back into a room until only the room's tone remains, the room is the weights and the recording is the activity. This idea asks whether a sound played into the room once can change the room's shape, so that a later, different recording comes out coloured by the first. The analogy carries that far. It stops at what is carried: a room's shape can hold a resonance, a general colouring, but it cannot hold a sentence. Whether a weight change is like that is what the experiment measures, and the analogy must not be allowed to answer it.

## 3. The technical elements, in ordinary words

**The context window and the key-value cache.** A language model predicts the next word from the words before it. The words it can see at once are its context, and the fixed maximum is the context window. To avoid recomputing, the model keeps, for every context token and every layer, two vectors called a key and a value; the store of these is the key-value cache, and it grows by a fixed amount per token. When the window is full, something has to be discarded or compressed. This is recalled, and it is standard.

**Weights against activations.** The model has two kinds of numbers. The weights are the fixed numbers learned during training; they define what the model is. The activations are the numbers that flow through it for one input; they are rebuilt from nothing for every new input. Learning from a context, in an ordinary model, changes activations only. This project is the exception: it moves one weight matrix. The first two sentences are recalled and standard; the last is established from the record.

**The Hebbian write.** At the chosen matrix, the rule watches the vector entering, `x`, and the vector leaving, `y`, and accumulates the outer product, a matrix in which each entry is one entering number times one leaving number. Averaged over the tokens it saw and scaled by a step size, that matrix is added to the weights. The rule has no target, no error signal, and no knowledge of what will be asked later. At a feed-forward output site this is the amplifier form given in section 2. This is established from `plasticity.py` and register row C-10.

**How an outer-product matrix can store and retrieve.** If a matrix is built as the sum of outer products of keys and values, then multiplying it by a later query gives each stored value weighted by how well the query matches its key. When the keys are well separated, one value dominates, so such a matrix can perform a bound lookup without any further machinery. The softmax in ordinary attention, a step that turns match scores into sharp weights, makes the selection sharper; it is not what makes binding possible in the first place. The first draft of this note said otherwise and was wrong. This is recalled from those architectures' papers. What limits this project's write is different: its two operands are the input and output of one matrix on the same token, so no separately chosen key and value are ever stored, and what accumulates is an amplification of the context's own activity. That the amplifier form carries colouring rather than binding is an inference and the experiment's pre-registered expectation.

**How transfer is measured, and against what.** Run the model on the context followed by a query and record its next-word probabilities at the final query position; that is the reference. Run the query alone with the original weights; that is the baseline. Fold the context into the weights, clear it, and run the query alone again; that is the test. The score is the KL divergence from the reference to the test, a standard measure of how far one probability distribution over next words sits from another, in units called nats, where zero means the two are identical and a divergence of one nat means that, averaged over the reference's own predictions, the reference gives its outcomes about 2.7 times the probability the other distribution does. Where the context binds an answer, the score is instead the probability the test assigns to the whole answer, token by token, with the first token's probability recorded beside it. The decisive comparison is not against random noise but against the same write made from a **different context of the same class** and installed at the same size: only what the own-context write does beyond that is specific to the context. For a bound answer there is a second comparison, against the same write scored on queries that keep the frame but not the entity, because a write that raises the answer token everywhere has primed a word rather than bound it. The reason for both is in section 5. This is a method, and the pilots ran the first comparison.

**Two confounds the measurement has to carry.** First, in the reference the query sits after the context's tokens, and in the baseline and test it sits after the start token alone; GPT-2 knows absolute positions, so part of the reference-to-baseline distance is position, not content, and no write at one site can close that part. The protocol records two further references beside the baseline, a neutral filler passage of the same length and a run in which the query's tokens keep the positions they had after the context, and claims that neither bounds the confound: on the pilot contexts the filler sits further from the reference than the query alone does for two of the three classes (`experiments/output_exp004/measurements_v1.json`, `position_control`). Second, the first query position sits next to the start token in the query-alone runs and dominated the first pilot's average; it is excluded from every decision. Both are established by measurement, in that file and in the pilot records.

**The loop as a possible consolidation step.** The parent's loop iterates the model on its own state with no input, and its injection overwrites the first block's input wholesale, so from the first iteration the context survives only as a sequence length; that is established from the parent's `docs/TECHNICAL.md`. One published method, Lee and colleagues below, folds context into weights after an offline pass over stored context. This project's loop can run before the fold with no stored context. Comparing the write made straight from the context with the write made after many loop iterations asks whether anything specific to the context survives the loop. Measured on two topic contexts at the pilot site, the writes made after ten loop iterations have a cosine of 0.96 with each other, against 0.41 for the writes made straight from the two contexts, and each sits within 0.03 of orthogonal to its own context's write (`measurements_v1.json`, `loop_writes`). That is established for those two contexts; that ten held-out contexts behave the same is the pre-registered expectation and an inference.

**The sizes involved.** Arithmetic on published shapes, established for GPT-2 Small from the configuration loaded in this session and recalled for the larger model.

| Model and context | Key-value cache the context occupies | One weight change at a single feed-forward output matrix |
|---|---|---|
| GPT-2 Small, per token of context | 18,432 numbers: 12 layers, a key and a value each, 768 numbers wide | 2,359,296 numbers for the full matrix (3,072 by 768), or 3,840 for a rank-one change, a single direction in and a single direction out (3,072 plus 768) |
| GPT-2 Small, a 1,000-token context | 18.4 million numbers | as above; the weight change does not grow with the context |
| Llama 3.1 8B, a 100,000-token context, within its 128,000-token window | about 6.6 billion numbers (32 layers, 8 key-value heads of 128 numbers, a key and a value each), about 13 gigabytes at 16-bit precision | 58.7 million numbers for the full matrix (14,336 by 4,096), about 117 megabytes at 16-bit; a rank-8 adapter on it, the usual way such a change is stored, is 147,456 numbers, under half a megabyte |

Whether this project's write is close to rank one depends on what drove it: EXP-001's loop-driven write held 95.8 percent of its squared size in one direction (`EXP_001_RESULTS.md` section 4), but the context-driven writes from the pilots' four contexts held 42 to 80 percent (`measurements_v1.json`, `sigma1_share`). That is established for the cases measured.

## 4. Prior and related work, each in a few sentences

Each entry says what the work does, how it relates to the idea, and whether it was read from `PRIOR_ART.md` or is recalled from training. An independent review on 2026-09-05 fetched every arXiv link and confirmed that each resolves to the stated title and authors; the descriptions themselves are recalled where marked, and four were corrected in that review; a second review on 2026-09-06 re-fetched every link and corrected two titles to their current listings.

**Fast weights and the outer-product memory.** The project's difference from this family is that the model here is pretrained and frozen, and the rule is applied to it from outside.

- **Hopfield 1982, "Neural networks and physical systems with emergent collective computational abilities."** This is the origin of storing patterns as a sum of outer products in a weight matrix and reading them back by settling into an attractor. Its rule is fixed and sees no query, as this project's does; its network is built for the purpose, where this project's was not. This entry is recalled. https://doi.org/10.1073/pnas.79.8.2554
- **Ba, Hinton, Mnih, Leibo and Ionescu 2016, "Using Fast Weights to Attend to the Recent Past."** This work adds to a recurrent network a second, fast-changing weight matrix updated by an outer product of recent activity, as a short-term memory beside the slow trained weights. The two-timescale picture, fast weights holding the recent past and slow weights holding what was learned, is the picture this idea sits in. This entry is recalled; `ALIGNMENT_REVIEW.md` finding F10 names it as missing from `PRIOR_ART.md`. https://arxiv.org/abs/1610.06258
- **Schlag, Irie and Schmidhuber 2021, "Linear Transformers Are Secretly Fast Weight Programmers."** This work shows that attention with a linear weighting is exactly a fast-weight memory: the context becomes a matrix built from outer products of keys and values. It is the entry that makes a Hebbian matrix a context store on paper, with the condition the prior-art file states. This entry is verified in `PRIOR_ART.md`. https://arxiv.org/abs/2102.11174
- **Irie, Csordás and Schmidhuber 2022, "The Dual Form of Neural Networks Revisited."** This work makes the same equivalence general: any linear layer trained by gradient descent can be written as attention over its training examples, so weights and stored examples are two views of one thing. This entry is verified in `PRIOR_ART.md`. https://arxiv.org/abs/2202.05798
- **Yang, Kautz and Hatamizadeh 2024, "Gated Delta Networks: Improving Mamba2 with Delta Rule."** This is a linear-attention variant whose memory matrix is updated by the delta rule, an outer-product write with an erase term keyed on the input, related to but not the same as Oja's rule, the braked Hebbian rule this repository also implements, whose brake is keyed on the output. This entry is recalled. https://arxiv.org/abs/2412.06464

**In-context learning as a weight update in disguise.** The project's difference from this family is that it makes the weight update real and installs it, where these works show that a context behaves as if one had happened.

- **von Oswald and colleagues 2023, "Transformers Learn In-Context by Gradient Descent."** This work constructs transformers whose forward pass over a context is one step of gradient descent on the context, so that learning from context and learning into weights are the same computation. This entry is recalled. https://arxiv.org/abs/2212.07677
- **Dai and colleagues 2023, "Why Can GPT Learn In-Context? Language Models Implicitly Perform Gradient Descent as Meta-Optimizers."** This work argues that a pretrained transformer's attention over context produces an implicit weight update and measures that it behaves like fine-tuning. It performs no write of its own. This entry is recalled. https://arxiv.org/abs/2212.10559
- **Todd and colleagues 2023, "Function Vectors in Large Language Models."** This work finds that the effect of a task-demonstrating context can be captured as a single vector in the residual stream and added into a later run with no context, transferring the task. It is context-to-activation transfer, one step short of context-to-weight, from a frozen model with a fixed procedure, as here. This entry is recalled. https://arxiv.org/abs/2310.15213
- **Hendel, Geva and Globerson 2023, "In-Context Learning Creates Task Vectors."** This is the same finding from a second group at the same time. This entry is recalled. https://arxiv.org/abs/2310.15916

**Architectures that update weights while reading.** The project's difference from this family is that the model here is frozen and was never trained to be written into, and the rule is fixed rather than learned.

- **Sun and colleagues 2024, "Learning to (Learn at Test Time): RNNs with Expressive Hidden States."** This work makes the hidden state of a sequence model a small weight matrix, updated by a gradient step on each token as it is read, trained end to end. This entry is recalled. https://arxiv.org/abs/2407.04620
- **Behrouz, Zhong and Mirrokni 2025, "Titans: Learning to Memorize at Test Time."** This work adds a neural memory module updated at inference by a surprise-weighted rule, with forgetting, alongside ordinary attention, evaluated at up to hundreds of millions of parameters. This entry is recalled. https://arxiv.org/abs/2501.00663
- **Chaudhary 2025, "Enabling Robust In-Context Memory and Rapid Task Adaptation in Transformers with Hebbian and Gradient-Based Plasticity."** This work compares a Hebbian fast-weight rule against a gradient rule inside small transformers trained from scratch, finding the Hebbian rule better at few-shot memory. It is the nearest work on rule family; its rule is learned and its model is trained for it. This entry is verified in `PRIOR_ART.md`. https://arxiv.org/abs/2510.21908

**Folding context into weights as a procedure.** The project's difference from this family is that the fold here needs no gradient and no training of the model.

- **Snell, Klein and Zhong 2022, "Learning by Distilling Context."** This work fine-tunes a model without the context to match the same model's outputs with the context, so the context's effect moves into the weights by gradient descent. It is the trained rung of the ladder `EXP_004_SPEC.md` proposes. This entry is recalled. https://arxiv.org/abs/2209.15189
- **Eyuboglu and colleagues 2025, "Cartridges: Lightweight and General-Purpose Long Context via Self-Study."** This work trains a small key-value cache offline, by having the model quiz itself on a long document, so the document can be served without the full cache. It is context compression by training, aimed at the same memory cost. This entry is recalled. https://arxiv.org/abs/2506.06266
- **Lee, McLeish, Goldstein and Fanti 2026, "Do Language Models Need Sleep? Offline Recurrence for Improved Online Inference."** This work periodically pauses, runs offline recurrent passes over the accumulated context, folds it into fast weights with a learned rule, and discards the key-value cache. It is the closest published shape to the idea; its rule is learned, its model is trained for the procedure, and its offline pass reads stored context where this project's loop reads nothing. This entry is verified in `PRIOR_ART.md`. https://arxiv.org/abs/2605.26099

**Editing weights directly, with knowledge of the query.** The project's difference from this family is the one register row C-43 states: the write here is derived with no target, from the model's own activation statistics.

- **Meng, Bau, Andonian and Belinkov 2022, "Locating and Editing Factual Associations in GPT" (ROME).** This work writes a single fact into a mid-stack feed-forward output matrix of GPT-2, the same site class this project uses, by a closed-form rank-one edit computed from a key for the fact's subject and an optimised value for its target. Register row C-43 records that it is not yet in `PRIOR_ART.md`. This entry is recalled. https://arxiv.org/abs/2202.05262
- **Meng, Sharma, Andonian, Belinkov and Bau 2023, "Mass-Editing Memory in a Transformer" (MEMIT).** This work extends ROME to thousands of facts across several layers by least squares, the method of fitting a matrix to map given inputs to given outputs with the smallest total squared error. It is the model for the query-blind least-squares rung of the ladder. This entry is recalled. https://arxiv.org/abs/2210.07229

**Latent reasoning, for where the parent's loop sits.**

- **Hao and colleagues 2024, "Training Large Language Models to Reason in a Continuous Latent Space" (Coconut).** This work feeds the model's final hidden state back in as its next input and trains it to reason that way. The parent's note of 2026-09-04 identifies the ATR loop as Coconut's latent mode with the training removed. This entry is recalled. https://arxiv.org/abs/2412.06769

**The biological frame.**

- **McClelland, McNaughton and O'Reilly 1995, "Why there are complementary learning systems in the hippocampus and neocortex."** This is the theory that the brain keeps a fast store for episodes and a slow store for structure, and consolidates from one to the other offline, during sleep. The fast-and-slow, context-and-weights picture in machine terms is this picture. This entry is recalled. https://doi.org/10.1037/0033-295X.102.3.419

## 5. The pilots, with their limits first, and what the first three got wrong

**Limits.** One site, `blocks.6.mlp`, the sixth block's feed-forward output matrix. One forward pass over each context, so one write. One context per class. No loop. Ten seeded random writes per cell, the same ten directions for every context. The drift ceiling was set to 100 percent and did not fire at this site; the largest step size reached 17.7 percent drift. Scratch code, run once each. The operator has ruled these are to be given little weight, and nothing here enters the register. Every number in this section is in `experiments/output_exp004/pilot_v4.json` or `measurements_v1.json`, and the full tables are in `experiments/output_exp004/PILOT.md`.

**The first pilot is withdrawn.** It tokenised the context and the query separately and joined the token lists, so for two of the three contexts the reference was the model on a token sequence GPT-2 would not produce for the joined text. It averaged the score over all query positions. Its random control was matched on overall size, the control register row C-23 retired, and drawn once without a seed. Its fact query asked for the country, not the bound city. Its one positive reading, a fall in the topic context's mean score from 1.918 to 1.836, was examined in review position by position: the fall sat entirely at the first query position, and at the final position the write made things worse. The first draft of this note reported that reading as the pilot's finding, and that was wrong.

**The second pilot's fact context could not test binding, and the earlier drafts gave the wrong reason.** It introduced its invented city indirectly, "The capital of the small nation of Veltoria is a city called Marrowgate", and GPT-2 Small gave the name's first token a log probability of minus 11.3 with the context present, below the minus 8.9 it gave with no context. The second and third drafts of this note said the model "does not reproduce a rare multi-token name in context" and quoted a screening of eight candidates that was never committed; its "1.2 nats" for Marrowgate cannot be reproduced and is withdrawn. The committed screening (`measurements_v1.json`, `screening.facts`) shows the cause was the phrasing: the same name stated in the protocol's verbatim format, "The capital of Veltoria is Marrowgate.", is the model's top prediction with the context present, at a log probability of minus 0.27, and eight candidates in that format with common single-token answers all pass, with gaps of 8.6 to 13.2 nats over the no-context baseline. That is established. The protocol screens every fact and format context on the frozen model first, and requires both a gap and that the answer be the model's top prediction, because the indirect Marrowgate context has an eleven-nat gap to an answer the model still does not give.

**The third pilot scored the wrong thing for the format class.** Its bound answer " GARDEN" is three tokens, and the third pilot scored the first, ` G`, which begins 468 entries in the vocabulary. The fourth pilot scores the whole answer, token by token, and keeps the first token beside it. The third pilot's check that the rule was absent during the query passes was an assertion placed after the call that clears what it asserted, so it could not fail; the fourth pilot counts hooks at the site after every query pass and runs a deliberate leak that shows the detector fire. Both are established from the scripts and the review.

**The fourth pilot.** Joint tokenisation, scores at the final position only, the whole bound answer and its first token recorded, ten rank-one random writes matched on the largest singular value, writes from the other two contexts installed at the same size (the swap control), a baseline rescaled in temperature to match the test's spread, the gate on every context pass, and the leak arm. Every arm it computes the same way as the third pilot is bit-identical to the third pilot's, 138 fields compared.

**The pilot reading.** On a fact the model binds in context with a gap of 11 nats, the own-context write moves the bound answer the wrong way at every drift. At drifts up to 5.9 percent the writes made from unrelated contexts move it the right way and the random and temperature controls move it by no more than 0.04 nats; at 17.7 percent the topic-swapped write also moves it the wrong way and the best random draw moves it the right way by 0.29 nats. So, at drifts up to 5.9 percent, a single write at this site carries no binding and is worse for the bound answer than a write from a context that never mentioned it. On the format context the own-context write is the best arm on the whole answer at drifts up to 4.1 percent, by 0.6 nats over the baseline and by more than a nat over the swapped writes, and the worst arm but one at 12.2 percent; the first-token gain the third pilot reported at 12.2 percent is real and is paid for twice over on the tokens that follow. On the topic context the own-context write lowers the score by 0.09 nats where both swapped writes raise it, an effect below the 0.1-nat floor the protocol now sets. These are one context each at one site.

**What the reading cannot say, established by a further measurement.** On three fact contexts in the verbatim format, the own write's effect on the bound answer after its own query was minus 0.70, plus 0.40 and plus 1.31 nats, so the fact reading above holds for one context of three; and the write from "The capital of Morvane is Tokyo" lifted ` Tokyo` by 1.54 and 1.59 nats after "The capital of Norway is" and "The capital of France is", more than after its own query (`measurements_v1.json`, `binding_vs_priming`). A score taken on the entity query alone would have counted that as binding. It is priming of a token, and the protocol now subtracts the control-query lift before deciding anything. Whether the amplifier form carries colouring and not binding remains the pre-registered expectation, and an inference.

## 6. What remains, and what needs the operator's decision

What happened: this note recorded the idea, traced it to the record and to one conditional entry in the prior-art file, explained its parts, described nineteen related works with links verified to resolve, ran four pilots, withdrew the first, replaced the second's fact context, corrected the third's score, and was revised against five independent reviews and three Codex rounds, the last three reviews finding that the protocol's fact score could not tell binding from priming. What it means: the project's write channel is Hebbian in form, a Hebbian matrix can store context, and whether this one stores anything specific to a context is an open, cheap, measurable question; the pilots suggest a small context-specific effect for topic and, at small drifts, for format, and none for binding on the one fact tested, with the write moving away from a fact the model binds in context on one context of three. All of these readings are inferences.

What remains, in order of information per unit cost, none of it started:

1. **Read and amend `EXP_004_SPEC.md`**, in its third revision, with rows C-69 to C-71 entered as open. The cost is a reading.
2. **Build and screen the context pool.** At least forty candidates per class in the spec's formats, screened on the frozen model, the first twenty that pass forming each class. The cost is minutes.
3. **Stage 1 and Stage 1b of EXP-004**, the development map and the held-out confirmation, with the same-class swapped-context control as the primary null and the control queries separating binding from priming. The cost is about four and three quarter hours of CPU.
4. **Stage 2, the loop before the write**, the comparison no published work has run. The cost is about a quarter of an hour, and it is worth running only if the topic class shows specific transfer in Stage 1b, since a loop write cannot be expected to carry what the direct write does not.
5. **Stage 3, the fidelity ladder.** The cost is hours, most of it the trained adapter.
6. **The prior-art additions in section 4.** Fifteen of the nineteen entries are not in `PRIOR_ART.md`. The cost is a reading session and a verification pass.

What needs the operator's decision:

- **Whether EXP-004 runs, and which stages.** The recommendation offered is the screening and the gate first, then Stages 1 and 1b, then Stage 2 only if the topic class passes Stage 1b.
- **Whether all four pilot outputs stay in the repository.** They are committed so every number quoted here cites an artifact, with the first marked superseded, the second's fact context marked as failing screening, and the third's format score marked as the wrong token. The recommendation offered is to keep them.
